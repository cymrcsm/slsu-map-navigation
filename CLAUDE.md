# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An offline touch-screen campus directory + wayfinding kiosk for Southern Leyte State University (a thesis project), plus a phone hand-off page reached by QR. Node/Express server, SQLite, vanilla JS front end on Leaflet 1.1.1. No bundler, no framework, no test runner — the front end is served straight from `public/`.

## Commands

```
npm start                 # node server.js → http://localhost:3000 (https on :3443 if certs/ exists)
npm run dev               # nodemon
npm run smoke             # 15 HTTP checks against a RUNNING server (routes, tiles, assets, admin auth)
npm run build:paths       # tools/build-walkpaths.js: floor SVGs → public/js/walkpaths.js
npm run build:data        # tools/build-data.js: both DBs → public/js/campus-data.js  (--check = report drift, exit 1)
npm run clean:svg         # tools/clean-floor-svg.js: hide routing strokes / transparent frame in a fresh Figma export (--check)
npm run db:init           # rebuilds db/slsu_directory.db FROM campus-data.js (destructive; rarely needed)
npm run phone-test        # LAN https server for testing live GPS on a real phone
node --check public/js/app.js   # the only syntax gate for front-end edits
node tools/build-web.mjs        # assemble web/ (GitHub Pages static copy of the phone page)
```

There are no unit tests. Verification is `node --check` on edited JS, `npm start` + `npm run smoke`, and looking at the page. `docs/ACCEPTANCE.md` has the manual checklist.

Repo files use **CRLF** line endings. When editing by script, match `\r\n`.

## Architecture

### Two databases, one generated data file

- `db/slsu_directory.db` — the published directory (read-only at runtime, `database.js`).
- `db/kiosk_overrides.db` — admin additions/edits/removals (`db/overrides.js`, table `overrides(id, kind ∈ custom|edit|removed, payload JSON)`). Kept separate so `db:init` can't wipe edits.
- `public/js/campus-data.js` — `CATEGORIES` + `LOCATIONS`, generated by `build:data` from both DBs. It is what the kiosk draws before the server answers and the **only** directory the phone pages have. A location added via the admin panel is invisible to phones until `build:data` is re-run and committed.

Both `.db` files are tracked in git even though `.gitignore` lists `*.db` (they were force-added). **Never `git checkout -- db/*.db` to "clean" the tree** — the server touches the file on every run, but a modified DB usually also carries real admin-added rows. Compare rows against HEAD first (`sqlite3` via node), commit real additions, then regenerate `campus-data.js`.

### Server (`server.js`)

Express: static `public/`, captive-portal probes, `/api/*` (locations, search, categories, buildings, overrides, config, health), `/go/:slug` → `mobile.html`, `*` → `index.html`. Admin writes go through `requireAdmin` — the code comes from `KIOSK_ADMIN_CODE` (default `@dm1n123`) and is never sent to the page. `/api/config` exposes `localUrl` (kiosk's own address) and `webUrl` (GitHub Pages copy, from `KIOSK_WEB_URL` or the gitignored `web-url` file) — these drive the two QR codes.

### Front end

- `public/js/app.js` (~2400 lines, numbered sections in comment banners: 4 map, 6 kiosk position, 8 markers, 9 detail panel, 10 search, 11 routing, 12 events, 14–16 add/move/edit pins, then admin cancel/return-to-panel and the on-screen keyboard at the end). Reads `PLACES` = `campus-data.js` layered with the server's overrides snapshot (`buildPlaces()` drops base entries a custom row also covers).
- `public/js/mobile.js` + `mobile.html` — the phone page. `ON_KIOSK` (from `<meta name="kiosk-hosted">`) distinguishes the kiosk-served copy from the GitHub Pages build; `HAS_FLOOR_PICKER = !ON_KIOSK`. `tools/build-web.mjs` strips that meta and the `<base>` when assembling `web/`.
- `public/js/routing.js` (`WalkRouting`) is the phone's A\* router; **app.js section 11 carries its own inline copy** (`findWalkingPath`, `projectOntoNetwork`, `splitByLevel`, `drawRoute`). Any change to routing rules (OFFPATH_LIMIT, stair-run expansion, snapping) must be made in both.
- `public/js/georef.js` — the single drawing-units ↔ lat/lng transform. Drawing space is the 320×570 `FRAME`, 1 unit ≈ 1 m, y down. `geo-overlay.js` is the custom Leaflet `GeoImageOverlay` for the floor SVGs.
- `public/js/handoff.js` — builds the QR URLs (`vendor/qrcode`, offline).
- Function-wrap pattern is used to extend behaviour without editing originals: `const xBase = x; x = function () { ...; xBase(); }` (see `syncWithServer`, `chooseSuggestion`, `openAdminPanel`, `closeAdminPanel`, `lockAdmin`).
- CSS palette lives in tokens at the top of `style.css` (`--slsu-navy-deep: #12294D`, `--route-line`, `--danger-color`). The kiosk has no mouse: use `:active`, not `:hover`. `--surface-hover` is a colour token, not a hover state.

### Floor artwork and the walk network

`public/assets/{ground,second,third}Floor_layer.svg` are Figma exports drawn stacked on one coordinate plane; each file is the floor below plus the new storey. Routable lines are `<path>`s keyed by stroke colour:

| floor | walkway | stair START | stairs / ramp | stair FINISH |
|---|---|---|---|---|
| ground | `#1E1E1E` (in every file) | — | — | — |
| 2F (`secondFloor_layer.svg`) | `#B9B30C` | `#047319` | `#BB7CBD` | `#171AC5` |
| 3F (`thirdFloor_layer.svg`) | `#C4B50C` | `#0A15DA` | `#8E0891` | `#05930E` |

One palette per floor (`FLOORS` in `build-walkpaths.js`); a stroke outside the palette of the file it appears in is ignored (e.g. the retired `#860808` 2F walkway still inside the third-floor export). The chain in a file links the floor below to that floor.

`build:paths` dedups walkway lines across files by geometry, snaps endpoints (`SNAP = 0.5`), ties each stair mouth to the nearest point on a corridor within `MAX_SNAP = 8`, and emits `nodes/edges/links`; `links = [a, b, kind, cost, along]` where `along` is the stair polyline foot→head used to draw the route up the stairs. It also prints stranded fragments and pins without a route — read that report after every rebuild.

**Walkpath rule (from the owner, non-negotiable):** routes must strictly follow drawn lines. The only allowed off-line hops are kiosk → nearest walkway, ground walkway → stair START, and stair FINISH → 2F/3F walkway. Never add synthetic bridging edges to the network; a pin that can't route within `OFFPATH_LIMIT = 2` units is fixed by the owner drawing lines, not by code. When the owner re-exports a floor with an updated ground walkway, apply the `#1E1E1E` paths to all three SVGs, remove the old ground-walkway paths, and leave the 2F/3F/stair layers and the green oval rect ("Rectangle 2612") untouched; then `clean:svg` and `build:paths`.

Route rendering: colour `#12294D` on both kiosk and phone; opacity keyed to the selected floor (`ROUTE_RUN_OPACITY = [1, 0.3, 0.12]` in app.js).

### Deploy

`.github/workflows/deploy-web.yml` runs `build-web.mjs` and publishes `web/` to GitHub Pages on pushes to `main` that touch phone-page files. Work is pushed directly to `main`. `deploy/` and `docs/KIOSK-DEPLOY.md` cover the Raspberry Pi access-point + trusted-cert setup.
